# SIGNAL ARENA · СПЕЦИФИКАЦИЯ UI, ГРАФИКИ И АССЕТОВ

**Версия 1.1** · для Phaser 4 + TypeScript + Vite · production-ready база для прототипа и MVP

---

## 0. Назначение

Документ фиксирует, какие визуальные элементы SIGNAL ARENA создаются кодом, вектором или растром; как они именуются, грузятся, кэшируются и применяются в Phaser.

Цель — не сделать «UI только в SVG», а заранее не тратить вес, память и время художников на растровые ассеты там, где компонент должен быть динамическим, переиспользуемым или масштабируемым.

> Растр — там, где он несёт художественную ценность.  
> Вектор или код — там, где элемент функциональный, повторяемый, масштабируемый или меняет состояние.

---

## 1. Базовые правила

1. **Функциональный UI по умолчанию создаётся кодом или вектором.**
2. Иконки и логотипы хранятся как оптимизированные SVG-исходники.
3. Панели, рамки, бейджи, шкалы, прогресс-бары, разделители, теги и свечной график рисуются средствами Phaser Graphics, rexUI и Phaser Text.
4. Растр используется для сущностей, иллюстраций, фонов, текстур, редкой косметики, splash-экранов и store-preview.
5. Обычный UI нельзя поставлять PNG-файлами. Исключение: требования ОС/сторов, сложная запечённая художественная фактура и минимальные texture-atlas ассеты после профилирования.
6. SVG — формат исходника. В рантайме Phaser использует SVG-текстуры или собранный атлас; DOM-SVG не является основой игрового интерфейса.
7. Каждый ассет имеет запись в manifest: идентификатор, pack, тип, источник, размер, lazy-политику, лимит веса и назначение.
8. Иллюстрации никогда не блокируют старт первого сценария.
9. Любой ассет без продуктовой или визуальной функции не производится.
10. Художественный стиль: грязное современное городское фэнтези, панк-таблоид, фактура печати, зерно, промышленная материальность; не стерильный fintech и не глянцевый NFT-арт.

## 3. SVG-иконки

### 3.1 Общие правила

| Параметр | Требование |
|---|---|
| Исходный формат | SVG 1.1 |
| Сетка | 24×24 |
| Safe area | 20×20, отступ 2 px |
| Stroke | 1.5 px на 24 px; 1.25 px для 16 px-версии при необходимости |
| Углы и соединения | `round` |
| Цвет | `currentColor` в исходнике; tint в Phaser |
| Заливка | Допустима вторым слоем с opacity до `.18` |
| Запрещено | `<image>`, embedded raster, filter, blur, mask, gradient, text outlines без необходимости |
| Оптимизация | SVGO, обязательный `viewBox`, без фиксированных `width`/`height` |
| Лимит | ≤ 400 B на простую иконку после SVGO; весь core-набор ≤ 12 KB source |
| Доступность | У интерактивной зоны есть текстовый `aria-label` в DOM accessibility overlay; сама Canvas-иконка не является единственным носителем смысла |

### 3.2 Runtme pipeline

```text
SVG source
  → SVGO
  → asset manifest
  → Phaser SVG texture loader или build-generated texture atlas
  → tint по semantic token
  → Phaser/rexUI component
```

Не использовать DOM-спрайт `<use href="#i-name">` как основной способ рендеринга внутри игры. Он допустим на web-лендинге и в системных DOM-слоях, но не является базой Canvas UI.

| Аватар | 28×28 | 44×44 |

## 7. Сущности

Всего запланировано 33 сущности. Их canonical display names остаются на английском. Функциональные описания, категории, правила и всё пояснение локализуются через copy keys.

### 7.1 Набор ассетов на сущность

| Ассет | Source size | Формат | Лимит | Применение |
|---|---:|---|---:|---|
| `thumb` | 232×232 | WebP | ≤ 25 KB | сетка Бестиария, 116×112 logical |
| `card` | 236×236 | WebP | ≤ 30 KB | коллекция, разбор, карточка |
| `hero` | 724×340 | WebP | ≤ 90 KB | экран сущности / крупное раскрытие |
| `locked` | 232×232 | WebP или SVG mask | ≤ 6 KB | закрытое состояние |
| `icon` | 24×24 | SVG | ≤ 400 B | журнал, теги, разбор |

Ориентир: до 150 KB полного набора на одну сущность. Все сущности лениво грузятся по pack/разделу; первый сценарий не грузит hero art бестиария.

### 7.2 Состояния

- `unseen`
- `discovered`
- `encountered`
- `mastered`
- `variant-{id}`
- `seasonal-{id}`

Не требуется рисовать все состояния на MVP. Naming и asset manifest должны их поддерживать с начала.

### 7.3 Правила рисунка

1. В portrait/cell crop персонаж остаётся в safe area не менее 88% полотна.
2. Взгляд/главный жест направлен к центру композиции.
3. Фон thumbnail/card — тёмный, простой, без текста и без реальных брендов.
4. Один доминирующий цвет категории + кислотный акцент; не превращать изображение в одноцветный фильтр.
5. Никаких логотипов бирж, монет, реальных людей или узнаваемых торговых интерфейсов.
6. Зерно, грубая печать, мазки и текстуры запекаются в растр; не воспроизводятся десятками фильтров в рантайме.
7. Враг всегда является визуальной метафорой конкретной угрозы, ошибки или когнитивного искажения.

## 9. CandleChart и кодовая графика

Свечной график, уровни, скрытая историческая часть, decision marker, risk markers, прогресс, шкалы, рамки и разделители не производятся как картинки.

### CandleChart layers

- `gridGraphics`
- `candleGraphics`
- `overlayGraphics`
- `markerGraphics`
- `maskGraphics` для скрытого future window
- `interactionZone`
- `labelContainer` только для редких подписей

### Ограничения

- Не создавать один Text на каждую свечу.
- Не делать tween на каждую свечу при reveal.
- Не перерисовывать все свечи при hover/выборе карты.
- Видимый набор на mobile: ориентир 40–120 свечей.
- Сложные terminal-like панели, order book, цена входа и полный набор индикаторов не входят в график.

## 10. Asset manifest

Ни один ассет не должен подключаться вручную из конкретной Scene.

```json
{
  "id": "entity.fake-breakout-phantom.hero",
  "kind": "image",
  "src": "assets/entities/fake-breakout-phantom/hero.webp",
  "pack": "bestiary-core",
  "lazy": true,
  "logicalSize": { "width": 362, "height": 170 },
  "sourceSize": { "width": 724, "height": 340 },
  "maxBytes": 92160,
  "category": "market-structure"
}
```

Для иконки:

```json
{
  "id": "icon.arena",
  "kind": "svg",
  "src": "assets/icons/i-arena.svg",
  "pack": "core-ui",
  "lazy": false,
  "logicalSize": { "width": 24, "height": 24 },
  "tintable": true,
  "maxBytes": 400
}
```

Manifest валидируется Zod в build pipeline. CI должен падать при превышении лимита веса, отсутствии файла, некорректном размере или невалидном naming.

| Что | Лимит / правило |
|---|---|

| Фон раздела | ≤ 120 KB |
| Первая hero-иллюстрация | ≤ 90 KB |
| Время до интерактива на среднем Android | ≤ 2.5 s — измерять на устройстве |

Phaser bundle оценивается отдельным budget, не смешивается с лимитом first content pack.

## 12. Тексты и tone of voice в прототипе

Все видимые тексты прототипа должны соответствовать стилистике SIGNAL ARENA. Технические идентификаторы (`taskId`, `P&L`, `token`, `premium`, `referral`) могут существовать в коде, но не должны попадать в пользовательский интерфейс случайно.

### UI-формула

> Функциональный заголовок + короткая атмосферная реплика.

Примеры системных состояний:

| Состояние | Заголовок | Подтекст |
|---|---|---|
| Loading | ЗАГРУЗКА ДАННЫХ | Рынок ищет оправдание. Подожди. |
| Offline | СВЯЗИ НЕТ | Хорошая новость: рынок тоже никуда не убежал. |
| Locked | ЗАПЕРТО | Сущность пока считает тебя недостаточно удобной жертвой. |
| Error | ДАННЫЕ НЕ ЗАГРУЖЕНЫ | Даже сервер иногда делает вид, что всё под контролем. |
| Saved | РЕЗУЛЬТАТ СОХРАНЁН | Теперь ошибка официально принадлежит истории. |
| No trade | ВНЕ РЫНКА | Сделка не открыта. Паника тоже. |

### Обязательные правила copy

- Шутка раскрывает механику, а не существует отдельно.
- Критическое действие всегда формулируется понятно; сатира идёт второй строкой.
- Не использовать нейтральные SaaS-заглушки в UI: `Victory`, `P&L`, `Early Access`, `Token Note`, `Referral Master`, `Founder Premium`, `Continue` без игровой причины.
- В alpha не показывать token/wallet/airdrop/листинг-разделы: токена на старте нет.
- XP, внутренняя валюта, достижения, ранги, карты и сущности разрешены и должны быть заметными игровыми элементами.
- Награда не должна визуально имитировать денежную доходность игрока.

### Пример verdict

```text
РЫНОК СОГЛАСИЛСЯ. ЭТО НЕ ЗНАЧИТ, ЧТО ТЫ БЫЛ ПРАВ.

КАЧЕСТВО РЕШЕНИЯ: 78/100
Контекст прочитан. Риск не развалился. Объём ты почти проигнорировал.

[СЛЕДУЮЩАЯ ОХОТА] [РАЗБОР]
```

## 13. Что не делаем

1. Не используем PNG для обычных UI-иконок, рамок, шкал, кнопок, графиков и текстовых элементов.
2. Не используем эмодзи и icon fonts как production-иконки.
3. Не грузим все сущности, фоны и косметику до открытия соответствующего раздела.
4. Не показываем токен, кошелёк, airdrop, листинг или баланс токена в alpha/MVP.
5. Не делаем иллюстрации, которые не связаны с угрозой, навыком, разделом или косметикой.
6. Не используем сложный SVG с фильтрами, шумом, огромным количеством paths и embedded raster только ради слова «vector».
7. Не превращаем desktop-версию в тяжёлый торговый терминал.
8. Не делаем visual effects, которые маскируют плохую иерархию или ухудшают читаемость данных.
9. Не используем цвет как единственный носитель статуса.
10. Не показываем внутреннюю валюту как внешнюю финансовую ценность.

## 14. QA перед production

### SVG

- Проверка всех иконок в 16, 20, 24 и 28 px.
- Проверка active, disabled, warning, danger, data и noise tint.
- Проверка на тёмном и светлом локальном фоне.
- Проверка touch target 44×44 для всех интерактивных иконок.
- SVGO и лимиты веса в CI.

### Растр

- WebP decode на целевых Android/iOS устройствах.
- Проверка crop и safe area на 1×, 2×, 3× DPR.
- Проверка lazy loading и placeholder.
- Проверка, что hero art не попадает в первый сценарий.
- Проверка визуального соответствия category color и силуэта.

### UI

- 320×568, 390×844, 430×932, 768×1024, 1440×900.
- Safe areas, bottom nav, bottom sheet, CTA, tab overflow.
- Reduce Motion.
- Offline/empty/error/loading states.
- Внутриигровые тексты не содержат случайных neutral placeholders.

## 15. Итоговое правило

> Код рисует то, что меняется.  
> SVG описывает то, что повторяется.  
> Растр хранит то, что создаёт мир.  
> Phaser собирает это в игру, а не в тяжёлый лендинг.
