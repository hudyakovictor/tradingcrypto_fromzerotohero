# ROLE_PROMPTS.md — ролевые добавки к BOOTSTRAP

> Использование: взять Вариант A/B из BOOTSTRAP_AGENT.md и **добавить** соответствующий блок после секции «РАБОТА». Роль сужает фокус и усиливает проверки, но не отменяет общий протокол.

---

## Роль: GAME CLIENT (сцены, UI, чарт, звук, PWA)

```text
ФОКУС: задачи T-P3-*, T-P4-04/10/11/12/14, T-P6-01/02/04/07, T-P8-02/04, T-P9-01/02.
ДОПОЛНИТЕЛЬНЫЕ ПРАВИЛА:
- Любой новый интерактивный элемент: состояния idle/pressed/disabled + пустое/ошибка/офлайн
  там, где они имеют смысл (SPEC 03 §13), и reduce-motion ветка анимаций.
- Пиксельные деньги запрещены: цвета/радиусы только из design-tokens.json; hex вне токенов = lint-брак.
- Перед DONE: visual-снапшот сцены обновлён осознанно (обновление снапа = отдельная строка в описании коммита).
- Бюджет: перерисовка по dirty-флагу; mission-сцена держит 50+ fps при CPU×4 (перф-хук window.__arena.perf).
```

## Роль: SERVER (Fastify, БД, WS)

```text
ФОКУС: задачи T-P2-*, T-P4-01/13, T-P7-01…05, T-P8-03, T-P9-08.
ДОПОЛНИТЕЛЬНЫЕ ПРАВИЛА:
- Всё, что уходит клиенту, валидируется исходящим .parse() (не только входящее).
- Итоговый score записывается только на сервере; клиентский скор — превью.
- Каждый маршрут: интеграционный тест fastify.inject + обновление apps/server/ROUTES.md.
- Миграции: up+down, обратимо; temp-БД в тестах; сиды не трогают user-data.
- Перед DONE: прогон блокирующей проверки честности (fore не отдаётся до attempts) — обязателен.
```

## Роль: SHARED KERNEL (контракты, скоринг, генератор, экономика)

```text
ФОКУС: задачи T-P1-*, T-P5-03, T-P6-06/09.
ДОПОЛНИТЕЛЬНЫЕ ПРАВИЛА:
- packages/shared — чистый: no Phaser, no node API в корневом barrel, no Math.random/Date.now.
- Любое изменение контракта: ADR + CONTRACT_VERSION bump + миграционная заметка; старые фикстуры
  продолжают парситься (или миграция).
- Скоринг: golden-кейсы immutable-исторические не меняются без ADR («угаданный верх + harmful ≤ 30»,
  «дисциплинированный выход 100» — канон).
- Перед DONE: snapshot-детерминизм генератора зелёный; покрытие пакета не упало ниже порога.
```

## Роль: CONTENT (сценарии, тексты, локали, арт-паки)

```text
ФОКУС: задачи T-P4-05…09, T-P5-*, T-P6-10, T-P9-06.
ДОПОЛНИТЕЛЬНЫЕ ПРАВИЛА:
- Каждый сценарий: валидатор зелёный + ручной чек-лист AUTHORING.md (вкладки только влияющие,
  brief ≤140 зн, обфускация заполнена, ≥1 acceptable/optimal решения, fore ≥12 свечей).
- Тексты только в тоне style-tone.txt; шкала жестокости 70–85 (99 — редко, Debrief/эпик).
  Запрет: бедность/болезни/реальные жертвы/живые личности. Дисклеймер 'НЕ ФИНРЕКОМЕНДАЦИЯ' нетронут.
- Арт: top1=иллюстрации сущностей, top2=карты (центр-объект, читаемость 96px), top3=фоны ≤30% шума.
  Промпты по content/art/prompts.md; каждый арт — с меткой pack/name в атлас.
- Перед DONE: content:check зелёный; в PR — визуальный снап новых сценариев (preview-инструмент).
```

## Роль: QA / GATEKEEPER (тесты, гейты фаз, ревизии сирот)

```text
ФОКУС: гейты фаз (ROADMAP), задачи *FIX*, T-P9-*, ревизионные закрытия сирот (§3.3),
проверка «реальность vs статус».
ДОПОЛНИТЕЛЬНЫЕ ПРАВИЛА:
- Твоя валюта — воспроизводимость: каждая находка = падающий тест или пункт чек-листа.
- REVIEW-FAIL: задача DONE, а DoD не выполнен → верни в TODO с комментарием, запиши в лог,
  нельзя молча чинить чужое DONE.
- На гейте фазы: прогони ВСЮ матрицу 07_TESTING §2, зафиксируй версии/хэши/метрики в GATE-записи.
- Если находишь «тихое» отклонение кода от спеки: либо FIX-задача, либо ADR — не оставляй оба.
```
