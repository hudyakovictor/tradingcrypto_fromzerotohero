# SPEC 00 — OVERVIEW: продукт, границы, стек, KPI

## 1. Продукт в одном абзаце

**Signal Arena** — игровой тренажёр качества торговых решений на исторических данных крипторынка. Игрок получает ситуацию из реального прошлого рынка, зафиксированную в точке решения `t0`, анализирует её через «браузер трейдера» (график + вкладки-источники + карты навыков), выбирает 1 из 4 решений (и иногда доп. шаг), после чего игра раскрывает заранее зафиксированное продолжение и оценивает **качество решения 0–100**, а не угаданное направление. Тренируемый объект — мышление: контекст, риск, неполная информация, когнитивные искажения, дисциплина.

Финальная формула (из конституции §18): *игрок не должен угадывать, куда пойдёт свеча — он должен научиться принимать решения, с которыми может жить, даже если рынок идёт не туда.*

## 2. Чем продукт является / не является (абсолютно)

| ❌ НЕ является | ✅ Является |
|---|---|
| мета-игрой («выращивание растений = крипта») | тренажёром решений на исторических данных |
| симулятором управления биржей | средой коротких повторяемых ситуаций |
| копией терминала в игровой обёртке | переводом теории трейдинга в узнаваемые навыки/угрозы |
| демо-счётом с виртуальным балансом | дополнением к реальному терминалу, не заменой |
| учебником «куда нажать для ордера» | системой, оценивающей процесс отдельно от исхода рынка |
| обещанием прибыли/«правильного прогноза» | |
| play-to-earn, выводимым результатом | |

Непересекаемые правила: (1) ничто не приближает игру к терминалу без продуктового обоснования; (2) ничто не заменяет трейдинг абстрактной мини-игрой; (3) нельзя поощрять частоту «сделок», завышенный риск, виртуальный PnL; (4) нельзя продавать преимущество в правильности ответа / качестве данных / риск-лимите / базовой защите; (5) сложность добавляет глубину анализа, не количество кнопок.

## 3. Продуктовые запреты (hard-block в коде и контенте)

- Запрещена покупка: правильных ответов, повышения оценки, лимита риска, фундаментальных защитных знаний, «сигналов».
- Запрещены механики, стимулирующие больше виртуальных «сделок».
- Запрещены лутбоксы, влияющие на качество решений; обещания окупаемости.
- Внутриигровая валюта не имеет денежной стоимости и не выводится. XP/ранг непередаваемы.
- Токен/NFT/блокчейн — НЕ часть MVP и НЕ часть релизной версии: отдельный гейт P10 (только исследование), ни одна строка кода не должна требовать токена.
- Будущее рыночных данных никогда не доступно клиенту до фиксации решения (см. 01_ARCHITECTURE §9).

## 4. Восемь контрольных вопросов (гейт любой фичи)

Перед реализацией фича письменно (в DoD задачи или ADR) отвечает:
1. Какой навык/искажение/тип решения тренирует?
2. Реализуема ли в браузерном каркасе без превращения в терминал?
3. Добавляет глубину, а не время и клики?
4. Награждает качество процесса, а не агрессию/удачу?
5. Может ли игрок объяснить, что перенесёт в реальный анализ?
6. Не создаёт ли обещание прибыли/сигнала/инвестрекомендации?
7. Не ухудшает ли доступность новичку?
8. Не делает ли опытного заложником примитива?

Нет «да» на 1–5 → фича не входит в ядро.

## 6. KPI-рамки (из конкурентного анализа, master)

- Удержание D1: рынок 27–32%, **цель продукта 40**.
- Сессия: 8–12 минут, 2–4 миссии за сессию → бюджет одной миссии **≤ 90 секунд** (contra-доказательство Kraken Learn 20–30 мин = слишком долго).
- Модель квоты «3 fix-миссии/день бесплатно» — валидирована (Brilliant/chess.com), кандидат **только для v2**, в v1 не строить.
- Ретейк задания разрешён бесплатно, но XP ×0.5 (ответ на Coinbase L&E).
- Streak-механика = «день с закрытой ошибкой», НЕ «день с кликом» (честная версия Duolingo).
- Этика = фича: геймифицируем анализ ошибок, а не частоту торгов (FCA/SSRN данные о вреде).
- RU-first, но архитектура локалей ≥ 10 языков с первого дня (плоские ключи) — Binance Academy: 44 языка = главный драйвер органики.

## 8. Стратегия репозитория данных

Цена продукта = исторические данные + детерминизм. Каждый сценарий хранит: источник, точку `t0`, версию датасета, **хэш скрытого будущего**, правила оценки, версию контента. До завершения задания игрок не видит идентифицирующих деталей (точная дата, редкое событие, оригинальные заголовки, уникальные цифры, точный идентификатор актива — там, где он выдаёт кейс). После завершения раскрываются: контекст, дата/инструмент (если допустимо), продолжение графика, источники, правила оценки, методика составления.

## 10. Что уже зафиксировано из референсов (важно для исполнителей)

- **Минимальный набор** (`minimal-set-elements-tasks-levels-1-to-99.png`): один каркас экрана масштабируется L1→L99: браузер с вкладками (иконки), адресная строка `arena://BTC-PERP · 15m`, чарт со штрих-уровнем и маркером DECISION POINT, 4 стеклянные карточки-сферы навыков со звёздами мастерства, 4 кнопки A/B/C/D. Сложность растёт плотностью и шумом, не новым каркасом.
- **Концепт-1** = минимальная база (RU-макеты миссии: order book «КИТОВАЯ СТЕНА», свечной чарт, карты ТРЕНД/ОБЪЁМ/РИСК/ЖДАТЬ с состояниями selected/locked). **Концепт-2** = лучший стиль текста, но эффект краски снизить ~30%; показывает Маркет и экран «ТЫ РАЗОБЛАЧИЛ ФАНТОМА». **Концепт-3** = самый полный набор экранов (Hub, Battle+AP-бюджет, Bestiary, Cards/Deckbuilder, Shop, Leaderboard, Quests) — 15–20% участков требуют переделки; использовать как карту разделов, не как пиксель-эталон.
- Правило карт навыков из брифа: **краткое название + значок**, без полноразмерной иллюстрации; объект средней детализации (между иконкой и иллюстрацией), читаемый на миниатюре.
- Правило вкладок: только те, что способны изменить решение; прогрессивное раскрытие 1–2 → максимум ~7; иконки заучиваются на память.
- AP-бюджет (attention points) из концепт-3 — **опциональная механика**, валидируется плейтестом в P4, до этого не зашивать в ядро (см. 04_GAME_LOGIC §7).
