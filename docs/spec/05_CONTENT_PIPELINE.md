# SPEC 05 — CONTENT PIPELINE: данные, авторинг, арт, тексты

Контент — код: живёт в `packages/content`, валидируется в CI, версионируется, релизится отдельно от бинаря.

## 1. Исторические данные

- Источник v1: публичные klines крупных бирж (spot/perp), снапшоты фандинга/OI при наличии; собственная выгрузка через скрипт `tools/fetch-klines.ts` (CCXT или REST вручную — зафиксировать в T-P5-01) в локальный датасет. Real-time не нужен никогда.
- Формат датасета: `datasets/<source>/<symbol>/<tf>.jsonl` (по строке на свечу, сортировано) + `registry.json`: `{ datasetId, version, sourceUrl, sha256, license, range }`.
- Правило честности: `sha256` датасета входит в сценарий; смена данных ⇒ новая версия, старые сценарии продолжают работать на старой версии.
- Держать сырые многолетние ряды в git ЗАПРЕЩЕНО (> лимитов репо): в git — только урезанные срезы, реально используемые сценариями (± past+fore с запасом), всё остальное — внешнее хранилище по решению в T-P5-01.

## 2. Авторинг сценария (ручной + генеративный)

Структура сценария: **историческая ситуация + условия рынка + сущность + доступные карты + протокол решения** (конституция §8).

- Ручной авторинг: `packages/content/scenarios/<id>.json` по SPEC 02 (обе половины: public + secret). Визуальный превью-инструмент (T-P5-07): отдельная Vite-страница, рендерит MissionScene-послойно из JSON без сервера.
- Генеративная вариативность: `scenario-gen` по seed из дерева параметров (сдвиг t0 внутри окна, шумовые reformulations brief'а, порядок/обертки решений, дистракторы) — НО зафиксированное per (seed, version). Генератор не трогает `fore`/рубрику (качество — человеком).
- **Валидатор CLI** `pnpm content:check` (T-P5-02), правила: zod-схемы; Σ весов рубрики = 100; ровно 4 решения; у ≥ 1 решения quality ≥ acceptable; `fore.length ≥ 12`; табы ⊆ влияющих (чек-лист автора); brief ≤ 140 символов; i18n-ключи существуют; хэши посчитаны; obfuscation-поля заполнены; визуальный снимок превью прикладывается к PR.

## 3. Матрица покрытия контентом (план набора)

| Ось | Значения |
|---|---|
| Тип ситуации | preEntry / inPosition (оба обязательны; inPosition ≥ 35% пула) |
| Сущность-категория | market / emotion / infonoise / risk / web3 |
| Протокол | none + 7 из LOGIC §5 |
| Тир сложности | 1–5 |
| Трендовый фон | выносливый тренд / флэт / вынос стопов / новостной шок / разворот |

MVP-пул 25–40 сценариев должен покрыть каждую категорию сущности ≥ 3 раза и каждый тир 1–3. Release-цель (P5-done): **150+ сценариев** + сезонные наборы. Распределение фиксируется в `content/coverage-plan.json` и проверяется валидатором.

## 4. Стартовые контент-пакеты (MVP объёмы)

- Сценарии 25–40 (матрица §3); карты 12 (LOGIC §9); сущности 8 (LOGIC §8); протоколы 3 первых; Академия 6 глав × 3–5 уроков (структура рынка / риск / позиции / таймфреймы / ликвидность / психология-искажения; Web3-риски — 7-я глава сразу после MVP).

## 5. Копирайт (закон текста)

- Все игровые тексты — `style-tone.txt`: панк-таблоидная криптосатира, короткие фразы, «формула 99/100», шкала жестокости 70/85/99 (99 — только Debrief/эпики), повторяющиеся мемы: «регуляторы обеспокоены», «рынок пересматривает реальность», «лыжи»/«агент»... (фиксируется словарик в `content/copy/style-glossary.md`, T-P5-06).
- Тексты Академии — тот же тон, но плотность пользы выше; каждая теория объясняет принцип, практика проверяет применение.
- Запрещённые темы юмора: бедность, болезни, реальные жертвы, конкретные живые личности по имени.
- Дисклеймер «НЕ ФИНРЕКОМЕНДАЦИЯ» — визуальный мем-печать на Debrief, обязателен; юридически корректные страницы — обычным языком (P9).

## 6. i18n

- RU — мастер-локаль; EN — первый перевод (P5). Файлы `content/locales/<lang>.json`, **плоские ключи** (`mission.decision.enterLongNow`), плюрализация через ICU-формат.
- Архитектура сразу рассчитана на 10+ локалей (Binance-инсайт: локализация = органика). Тест: в EN отсутствующий ключ падает в RU + warning; ни один UI-строк не захардкожен (lint-скрипт `i18n:audit`, T-P5-05).

## 7. Арт-пайплайн

Источники стиля (master/ideas-ui.zip): **top1** — иллюстрации сущностей (тёмный комикс-рэндер: толстый контур, глубокие тени, неоновые акценты, атмосферная сцена; референсы: Headline Titan, Leverage Goblin); **top2** — вид карт (центральный объект средней детализации на тёмном поле, орнаментальная рамка, имя сверху/снизу, НЕ полноиллюстрация); **top3** — фоны/коллажи (газетные вырезки, граффити, стикеры; интенсивность ≤ 30%, см. концепт-2 «краски −30%»).

Правила производства:
- Каждый арт-файл: `assets-src/<pack>/<name>.png` → пакуется free-tex-packer в атласы `public/assets/atlas/*.{json,webp}`; в git — только атласы и PNG-мастера ≤ 2 МБ.
- Карты: объект по центру, поле молчащее, рамка из токенов; читаемость на 96px обязательна (проверка-скриншот в CI при наличии пайплайна).
- Сущности: сцена-портрет 1024×1280, glow-акцент цвета категории (market=голубой, emotion=фиолет, infonoise=оранж, risk=красный, web3=изумруд).
- Промпт-шаблоны генерации арта — в `content/art/prompts.md` (T-P5-09), чтобы стиль был воспроизводим любым агентом/инструментом.
- Логотип: 3 уровня детализации по brand-readme (compact S-марк / основной / app-icon; иллюстративные заставки — свободные). Эталоны — template_high/low в master.

## 8. Версия контента и релизы паков

`contentVersion = semver пакета content`. Клиент при старте сверяет версию; мисматч → контент-обновление до старта миссий. Каждый релиз контента: ченджлог + прогон валидатора + визуальные снапшоты новых сценариев в PR.
