# ROADMAP — фазы 0% → релиз → пост-релиз

Каждая фаза: **Цель → Объём (in/out) → Выходной критерий (гейт) → Тесты гейта**. Гейт прогоняется агентом, закрывающим последнюю задачу фазы, и фиксируется записью `GATE` в HANDOFF_LOG. Автоматические команды гейта — из 07_TESTING §2. Порядок фаз последовательный; внутри фазы задачи параллелятся, если граф зависимостей позволяет (колонка «Зависит» в TASK_BOARD).

Сводный график по трудозатратам (оценка в «агенто-сессиях» ~ одна задача): P0 9 · P1 10 · P2 9 · P3 22 · P4 16 · P5 12 · P6 10 · P7 8 · P8 8 · P9 10 · P10 4 ≈ **118 сессий**.

---

## P0 — Фундамент (9 задач)

**Цель:** `pnpm i && pnpm dev` поднимает пустой клиент (boot-сцена Phaser 4 на тёмном фоне) и сервер (`/health`), CI зелёный, протокол статуса действует.
**In:** монорепо, конфиги (ts/eslint/prettier), packages/shared init, apps/client + apps/server скелеты, CI, Playwright smoke, спайк rexUI × Phaser 4 (ADR-001), первый ADR-процесс.
**Out:** любой геймплей, реальные данные, rexUI-фичи.
**Гейт:** команды 07 §2 проходят локально и в CI; e2e `boot.spec` зелёный; ADR-001 принят одним из трёх решений.

## P1 — Shared-ядро: контракты, scenario-gen, скоринг (10)

**Цель:** все Zod-контракты SPEC 02 существуют, покрыты, есть эталонные фикстуры, движки скоринга/экономики/уровней — чистые функции с golden-тестами; генератор v1 детерминирован.
**In:** SPEC 02 целиком, scoring v1 (LOGIC §2), levels (§4), economy (§6), selector (§10), hash-lock утилиты, fixtures ×3, snapshot-детерминизм.
**Out:** серверные маршруты, UI.
**Гейт:** `pnpm -w test` зелёный с thresholds; контрактные антилик-тесты падают при подмешивании fore в Public (проверка проверки).

## P2 — Сервер MVP (9)

**Цель:** Fastify отдаёт миссии из контент-пака по контракту, принимает решения, отдаёт reveal с hash-проверкой; гостевая сессия; SQLite миграции.
**In:** env/auth/db плагины, drizzle-схемы, missions/attempts/reveal/profile/journal REST, WS-конверт, seed:test, интеграционные тесты каждого маршрута, rate-limit.
**Out:** турниры, маркет, платежи, реальный античит-анализ.
**Гейт:** integration-набор зелёный; `honesty`-ручка ведёт себя по SPEC 01 §9 (ручной curl-прогон приложить в GATE-запись).

## P3 — Клиентский каркас (22)

**Цель:** весь визуальный каркас игры по SPEC 03 на фикстурах, без сервера: сцены, виджет браузера, CandleChart, карты, решения, extra-step, reveal, debrief, навигация, звук, PWA-оболочка, i18n, сторы.
**In:** design-token loader, rexUI-интеграция по ADR-001, CandleChart v1/v2, MissionScene полностью, Reveal/Debrief, Hub-lite, NavService, Modal/Toast, SoundManager, stores+persist, i18n ru/en, netClient (mock-режим), PWA manifest+SW, visual-снапшоты сцен.
**Out:** реальные сетевые данные, онбординг-логика, адаптация.
**Гейт:** `mission.spec` против мок-резолвера зелёный; visual-базисы утверждены; perf-пробник чарта ≤ 2 мс.

## P4 — Вертикальный срез MVP (16)

**Цель:** играбельный MVP по конституции §17: сервер связан с клиентом, onboarding, стартовый контент-пак, журнал/академия/бестиарий лайт, офлайн-режим, честный reveal.
**In:** связывание netClient↔server, onboarding (10 шагов), 25–40 сценариев + 12 карт + 8 сущностей + 3 протокола + Академия 6 глав, journal v1, academy v1, bestiary v1, profile/settings lite, offline+outbox, стрик, плейтест-чеклист (≤ 90 с миссия).
**Out:** уровни полная матрица, дейли, турниры, маркет.
**Гейт:** e2e-набор 1–7 и 10 зелёный; полевой плейтест 3 человек (чек-лист приложен к GATE); ручная проверка «миссия ≤ 90 с» на 10 случайных сценариях.

## P5 — Контент-конвейер (12)

**Цель:** контент масштабируется: датасеты, валидатор, превью-инструмент, EN-локаль, арт-паки, копирайт-глоссарий; релиз контента 150+ сценариев.
**In:** fetch-klines + registry+hash, валидатор v2 (coverage-plan), превью-страница, EN перевод + i18n-аудит, арт: 8 сущностей + 12 карт + базовые фоны, глоссарий панк-стиля, сезонная структура паков, контент-релиз процесс (PR чек-лист).
**Out:** крауд-авторинг (P10), арт всех 35 сущностей (по мере надобности).
**Гейт:** `content:check` зелёный на полном паке; новый агент по `content/AUTHORING.md` создаёт сценарий, проходящий CI, за ≤ 30 мин (запись эксперимента в GATE).

## P6 — Метагейм (10)

**Цель:** удержание: уровни 0–99 на матрице устойчивости, дейли-квесты, стрик «закрытая ошибка», коллекции/инвентарь, паттерны v2, уведомления, нижняя навигация на 5 пунктов.
**In:** computeLevel матрица+UI, quests/dailies, streak+freeze за монеты, inventory UI, entity unlock через главы, pattern insights v2 (рекомендации), пуши-локальные (PWA notifications, опционально), настройки-расширенные.
**Out:** турниры, монетизация.
**Гейт:** e2e journal+метагейм зелёный; экономический симулятор-скрипт (bots 1000 сессий) показывает: положительный приток при ошибках и кап фарма (отчёт в GATE).

## P7 — Турниры / асинхронное PvP (8)

**Цель:** соревновательный слой на фиксированных наборах с серверной фиксацией и tie-break по приоритету (качество → протокол → доказательства → скорость).
**In:** CRUD турниров (через контент), entry/окна, leaderboard + tie-break, reveal-after-window, анти-аномалии флаг, share-картинка результата, duels (опционально за флагом).
**Гейт:** `tournament.spec` (2 аккаунта, идентичный seed-набор) зелёный; нагрузочный спот: 500 entries — leaderboard ≤ 2 с.

## P8 — Маркет и монетизация (8)

**Цель:** косметика-first экономика по конституции §13: витрина, IAP-абстракция с серверной валидацией чеков (stub-провайдер + интерфейс), сезонный пасс, подписка PRO (удобства, не сила).
**In:** MarketScene полный, каталог SKU (тема чарта, рамки, аватары, звук-паки, фоны, пасс), entitlement-флаги, «не влияет на бой» бейджи и автотест no-advantage, ценовые правила ($5–15 сезон / подписка-месяц), юнит конфигурации цен.
**Out:** реальные платёжные ключи (это ops-шаг релиза P9).
**Гейт:** `paywall.spec` + контрактный тест «нет поля силы в SKU» зелёные; юридический текст покупок отображён до оплаты.

## P9 — Полировка и релиз (10)

**Цель:** релиз-кандидат: производительность, доступность, аналитика KPI, стабильность, правовые страницы, стор-листинг, выпуск.
**In:** perf-аудит (бюджеты 07 §6), a11y-проход, аналитика событий (D1/сессия/миссии/воронка onboarding; first-party, без PII), crash/error reporting, правовые страницы («не финсовет», приватность, покупки), store assets + тексты (RU/EN), release build CI (tagged), soft-launch чек-лист, rollback-план.
**Гейт:** чек-лист релиза подписан (все пункты ✅ в GATE-записи); нагрузка API 100 rps 10 мин без ошибок; PWA install на 2 платформах вручную.

## P10 — Пост-релиз (4, только после PMF)

**Цель:** исследования, не обещания: токен/RFC (юридическая архитектура, токеномика, «работает при цене 0»), creator marketplace RFC, 10+ локалей накат, глубокая аналитика обучения (эффективность навыков).
**Дисциплина:** ничего из P10 нельзя смешивать с ядром; каждое направление — отдельный RFC и гейт заинтересованных.

## Приоритет при нехватке ресурса (если надо резать)

1. Режется: P10 целиком → P7 duels → P8 пасс → P6 пуши → P5 EN (отложить).
2. Не режется никогда: честность reveal (hash-lock), скоринг-качество, продуктовые запреты, onboarding, миссия ≤ 90 с, тестовые гейты.
