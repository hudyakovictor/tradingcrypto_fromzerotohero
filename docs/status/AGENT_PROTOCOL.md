# AGENT_PROTOCOL.md — протокол многоагентной эстафеты

Проект рассчитан на **долгий цикл и сменяющихся агентов**. Любой агент может оборваться в любой момент; следующий должен продолжить по записям, без устных пояснений. Этот файл — закон о том, как фиксируется состояние. Нарушение протокола = брак, даже если код хороший.

Три артефакта состояния:

| Файл | Роль | Кто пишет |
|------|------|-----------|
| `docs/roadmap/TASK_BOARD.md` | Истина по задачам: статусы, claim, зависимости | агент, меняющий статус задачи |
| `docs/status/STATUS.md` | Дашборд проекта: фаза, %, «сейчас в работе», блокеры, YAML-снапшот | агент при каждом изменении статуса задачи |
| `docs/status/HANDOFF_LOG.md` | Append-only хроника сессий: claim/progress/done/partial/blocked/adr | каждый агент минимум 2 раза за сессию (старт, финиш) |

---

## 1. Модель статусов задачи

```
TODO ──claim──▶ IN_PROGRESS ──DoD выполнен──▶ DONE
                    │  ├─ не закончил ───────▶ PARTIAL ──claim──▶ IN_PROGRESS
                    │  └─ нет возможности ───▶ BLOCKED ──разблокирован──▶ TODO
                    └─ сессия умерла молча ──▶ (сирота → см. §3.3)
DONE ──ревизия Failed──▶ TODO (статус + комментарий REVIEW-FAIL)
Любая ──устарела──▶ DEFERRED (с комментарием, куда переехала)
```

- `TODO` — свободна. Брать можно, если все зависимости в колонке «Зависит» = DONE.
- `IN_PROGRESS` — занята конкретной сессией. Поля: `Агент`, `Начата`.
- `DONE` — DoD выполнен **и** гейт тестов зелёный, есть commit-хэш в логе.
- `PARTIAL` — сессия закончилась, работа не закончена. Обязательные поля в строке задачи: `Сделано` / `Осталось` / `Точка продолжения`.
- `BLOCKED` — невозможно продвигать по внешней причине. Поле: `Причина` + что снимает блок.
- `DEFERRED` — отменена/слита с другой. Навсегда остаётся в доске (история).

## 2. Session ID и подпись

Каждая сессия имеет ID формата `ag-YYYYMMDD-XXX` (XXX — 3 буквы/цифры на выбор агента) или ID, выданный платформой (например `arena/01a07db6-…`). ID пишется в claim, лог и коммиты. Одна сессия = один ID, не выдумывать новый на каждую запись.

## 3. Холодный старт: алгоритм первых 10 минут

### 3.1 Чтение (обязательно, in order)
1. `AGENTS.md` → этот файл.
2. `STATUS.md` → YAML-снапшот: текущая фаза, активные задачи, блокеры.
3. `HANDOFF_LOG.md` → последние 10 записей.
4. `git log --oneline -15` → сверить реальность с записями.
5. `TASK_BOARD.md` → выбор задачи (§3.2).

### 3.2 Приоритет выбора задачи (сверху вниз)
1. **Сироты**: `IN_PROGRESS`/`PARTIAL`, чья сессия завершилась без финальной записи (§3.3) — подхватить.
2. **PARTIAL** любые — продолжить с «Точки продолжения».
3. **Ближайшие задачи** из `STATUS.md` → раздел «Ближайшие задачи».
4. Первый `TODO` текущей фазы с выполненными зависимостями.
5. Если фаза выполнена целиком — проверь **гейт фазы** в `ROADMAP.md`, задокументируй прохождение гейта отдельной записью, открой следующую фазу.

### 3.3 Протокол сирот (как понять, что IN_PROGRESS брошен)
Задача считается сиротой, если выполнено ЛЮБОЕ из:
- в HANDOFF_LOG нет записи о финале (DONE/PARTIAL/BLOCKED) этой сессии **и** есть запись другой сессии с более поздней датой;
- последний heartbeat записи по задаче старше 1 календарного дня;
- владелец сам пометил «сессию прервет» в чате/issue.

Действие с сиротой:
1. Прочитай её коммиты (`git log --oneline --grep="T-P*-NN"`).
2. Прогони тесты. Если зелёно и DoD фактически выполнен — закрой как `DONE` действием `REVIEW-CLOSE`, впиши свой ID.
3. Если частично — переведи в `PARTIAL`, сам заполни «Сделано/Осталось/Точка продолжения» по коду, затем claim.
4. Если работа вредная/не по спеке — откати (отдельный коммит `revert`), переведи в `TODO` с комментарием.

## 4. CLAIM (старт работы)

1. В `TASK_BOARD.md` у строки задачи: статус `TODO→IN_PROGRESS`, поля `Агент: <session-id>`, `Начата: <дата UTC>`.
2. В `STATUS.md`: перенеси задачу в секцию «Сейчас в работе», обнови YAML-снапшот (`active`, `updated_at`).
3. В `HANDOFF_LOG.md` — запись `CLAIM`:

```md
| 2026-09-08 14:02Z | ag-20260908-A1 | CLAIM | T-P3-07 | Беру CandleChart v1. План: рендер свечей+объёма, грид, ось цен. Зависимости DONE: T-P0-04 ✔ |
```

4. Коммит: `chore(status): claim T-P3-07 [ag-20260908-A1]` — **сразу**, до кода. Это твой заслон от гонок с параллельными агентами.

## 5. Во время работы

- Коммить маленькими шагами: `feat(client): …`, `fix(server): …`, `test(shared): …` (Conventional Commits, scope = пакет). В теле или скобах — ID задачи: `feat(client): candle grid renderer (T-P3-07)`.
- Heartbeat в HANDOFF_LOG при смене подэтапа или каждые ~60–90 мин, формат `PROGRESS`: что сделано, что дальше, есть ли риск не уложиться.
- Обнаружил пробел/противоречие в спецификации → не выдумывай: `docs/adr/ADR-NNN-<slug>.md` (шаблон `ADR-000-template.md`), статус `proposed`, запись `ADR` в лог. Реализацию делай по принятому тобой же ADR, если решение очевидно обратимо; иначе `BLOCKED`.
- Нет доступа к нужной команде/пакету — фиксируй в лог факт обхода (что не смог проверить).

## 6. DONE (завершение) — чек-лист, все пункты

1. ☐ Код соответствует `TASK_BOARD` → DoD задачи дословно.
2. ☐ `pnpm -w typecheck` зелёный.
3. ☐ `pnpm -w lint` зелёный.
4. ☐ `pnpm -w test` зелёный; новая логика покрыта (правила покрытия — `07_TESTING_STRATEGY.md`).
5. ☐ `pnpm e2e` зелёный, если тронуты сцены/серверные эндпоинты.
6. ☐ Контракты не изменены без ADR; если изменены — ADR принят, версия bumped, обе стороны применяют.
7. ☐ Доки синхронизированы: если реальность отклонилась от `docs/spec/*` — обнови спек в том же коммите.
8. ☐ `TASK_BOARD.md`: статус DONE, поле `Готово: <дата>`, короткий итог.
9. ☐ `STATUS.md`: прогресс фазы пересчитан, задача убрана из «Сейчас в работе», YAML обновлён.
10. ☐ `HANDOFF_LOG.md` — запись `DONE` с commit-хэшами и количеством тестов:

```md
| 2026-09-08 17:40Z | ag-20260908-A1 | DONE | T-P3-07 | CandleChart v1: свечи/объёмы/грид/ось. Тесты: 14 unit + 2 e2e ✔. След.: T-P3-08 (fog+reveal) свободна |
```

## 7. PARTIAL (не закончил сессию)

Лучше честный PARTIAL, чем лживый DONE. Обязательные поля в строке задачи и в логе:

- **Сделано**: перечень работающего (с тестами/без).
- **Осталось**: конкретные подпункты DoD.
- **Точка продолжения**: файлы, строки/символы, следующая команда. Пример: `packages/client/src/game/chart/CandleChart.ts: метод drawFuture() дописан наполовину — расчёт x-координаты готов, анимация нет. Следующий шаг: tween по revealIndex, см. UX_SPEC §4.6`.
- Рабочий код коммитится веткой как есть (сборка сломана — пометь `WIP` в коммите и в STATUS).

## 8. BLOCKED

- Поля: `Причина` (внешняя зависимость / нет решения / конфликт контрактов), `Разблокируется когда…`.
- В STATUS.md задача попадает в «Заблокировано».
- Агент берёт следующую доступную задачу — простой запрещён.

## 9. Гейт фазы

Фаза закрывается не «по ощущению», а когда: все её задачи DONE **и** выполнен «Выходной критерий фазы» из ROADMAP.md (команды + ручные проверки). Агент, закрывающий последнюю задачу фазы, обязан прогнать гейт и записать `GATE` в лог с результатом. Если гейт не пройден — создай дефект-задачи `T-P*-FIX-*` в доске текущей фазы и берись за них.

## 10. Запреты протокола

- Нельзя редактировать/удалять чужие записи HANDOFF_LOG (только дополнять свои).
- Нельзя менять статус чужой задачи без §3.3.
- Нельзя менять ID уже созданных задач (новые задачи — только новые ID).
- Нельзя дробить готовые DoD «на потом» без следов в доске.
- Нельзя писать в доску «почти готово» — есть только 5 статусов §1.
- Нельзя хранить состояние в чате, не дублируя в репо. Чат умирает вместе с сессией.

## 11. Формат записей HANDOFF_LOG (строгий, таблица MD, новые сверху)

`| ДатаUTC | Сессия | Тип | Задача | Суть |`

Типы: `INIT` (первая запись сессии: ID, цель), `CLAIM`, `PROGRESS`, `DONE`, `PARTIAL`, `BLOCKED`, `UNBLOCK`, `REVIEW-CLOSE`, `REVERT`, `ADR`, `GATE`, `RELEASE`, `NOTE`.

`INIT` пишется сразу после чтения §3.1 — до claim — чтобы сирота-детектор знал, что сессия жива.
